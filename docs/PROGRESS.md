## 演示任务

前置（只需一次）：在项目根目录执行 `npm install`

【1-1 本地开发模式：两个标签页连上服务器】：`npm run dev`，然后在浏览器打开两个 http://localhost:5173 标签页。每个页面都应显示"已连接"，传输方式为 websocket，在线连接数为 2。自动化验证：另开一个终端执行 `npm run smoke -- http://localhost:5173` → 当前结果：通过

【1-2 本地生产模式：构建后单服务运行】：`npm run build && npm start`，另开一个终端执行 `npm run smoke -- http://localhost:3000` → 当前结果：通过

【1-3 正式公网地址：页面可打开、WebSocket（wss）可连接】：`npm run smoke -- https://paint-rush.onrender.com`（Render 免费套餐闲置后会休眠，首次请求可能需要等待几十秒） → 当前结果：通过

【2-1 房间流程自动化验收（创建、两人入座互见、第三人满员、错误房间码、非房主不能开始、两端同步倒计时）】：`npm run accept:2 -- https://paint-rush.onrender.com`（本地：`npm run accept:2 -- http://localhost:3000`） → 当前结果：通过

【2-2 浏览器手动演示】：打开 https://paint-rush.onrender.com → 点"创建房间，邀请好友" → 点"复制邀请链接"，在另一个浏览器窗口（或无痕窗口）打开该链接 → 点"加入房间" → 两边都能看到双方 → 房主点"开始游戏" → 两边同时出现 3-2-1。再用第三个窗口打开同一链接，应看到"房间已满"；在首页输入 ZZZZ 并加入，应提示房间不存在 → 当前结果：通过（本地浏览器走查）

【3-1 核心玩法自动化验收（完整打一局，约 70 秒）：双方移动并互相看到、两端快照一致、涂色、连按不加速、乱序和重复输入被丢弃、碰撞和越界、结算一致】：`npm run accept:3 -- https://paint-rush.onrender.com`（本地：`npm run accept:3 -- http://localhost:3000`） → 当前结果：通过

【3-2 浏览器手动对战】：两个浏览器窗口按 2-2 的步骤进入同一房间 → 房主开始 → 两边都用方向键或 WASD 移动，确认能看到对方实时移动、走过的格子变色、顶部百分比和倒计时变化 → 60 秒后两边弹出相同的胜负横幅和百分比 → 当前结果：通过（本地浏览器 + 脚本对手）

【3-3 输入延迟诊断】：`npm run latency -- https://paint-rush.onrender.com` → 输出每次按键到服务器快照中出现位移的毫秒数（本地 4–100ms；沙箱到 Render 约 500–600ms，受沙箱出口网络影响）→ 当前结果：可运行（诊断工具，不设通过线）
